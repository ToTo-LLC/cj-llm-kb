## Gate discipline

- Every plan has an explicit demo gate. No plan is marked ✅ without a proof artifact (screenshot, recording, or test-run receipt) per the "Verification Before Done" rule in `CLAUDE.md`.
- Plan 07 is hard-blocked on plan 06 approval. All other sequencing is soft — earlier plans inform later ones but can overlap where contracts are stable.
- Lessons learned during plan N feed into [`lessons.md`](./lessons.md) and influence the authoring of plan N+1.
- After every plan completion: pause for user review before starting the next.

## Workflow per plan

1. Main loop authors (or refines) the plan file under `tasks/plans/`.
2. Execution via `superpowers:subagent-driven-development` — one fresh subagent per task, two-stage review between tasks.
3. Each step marked complete only with verification proof per the `CLAUDE.md` rule.
4. On plan completion: demo artifact captured → user review → mark ✅ here → update [`lessons.md`](./lessons.md) → author next plan.

## Review cadence

- **Section-by-section** feedback within a plan (per `CLAUDE.md` plan-mode directives).
- **Plan-by-plan** feedback at demo gates.
- Decisions surfaced as `AskUserQuestion` with ≤4 labeled options, recommended first, per the user's preference format (NUMBER.LETTER).

### Track A — production wiring residuals (architectural follow-throughs from Plan 16)

These are Plan 16 deferrals that surfaced in T31.5 / T34.5 / T39.5 reviews and were too small to warrant their own Plan 16 task at the time, but are real production-correctness gaps.

1. **brain_api production AnthropicProvider e2e test coverage** — T31.5 wired `LLMRequest.domain` at 7 production sites and T39.5 added the lifespan-side `AnthropicProvider` construction when the API key is present, but neither task added an end-to-end test that exercises the full `brain_api` → `AnthropicProvider` → leaky-bucket gate path with a real API key fixture. Today's coverage is unit + pin tests; production readiness requires a pytest-marked integration test or a manual QA receipt.
2. **brain_api `ConfigWatcher` doesn't update live `AppContext.tool_ctx.config` reference** — T35's `ConfigWatcher` clears `loader._cached`, and T39.5 added `_reset_ctx_cache` for brain_mcp, but brain_api's `AppContext.tool_ctx.config` is set once at lifespan startup and never re-read. Hot-reload works for fresh tool calls (each calls `resolve_config`), but any code path that inspects `app.state.tool_ctx.config` directly will see the stale snapshot. Audit + fix.
3. **T43 consumer migration to zustand stores** — T43 landed `budget-store.ts` + `domain-overrides-store.ts` but did NOT migrate the existing consumers (`panel-budget.tsx`, `panel-domains-row.tsx`, `domain-override-form.tsx`) — those still use direct `configGet` / `configSet` calls. Migration is mechanical but spans 3+ files; held for Plan 17 to keep T43 narrow.
4. **TS-side `AutonomyCategory` drift detection vs Python schema** — `AutonomyCategoryFlags` is defined twice (Python `Config.autonomous` + TypeScript types in `panel-autonomous.tsx` / API client). T37 + T40 reviewers flagged the drift risk. A schema-source-of-truth generator (e.g., pydantic2ts) would eliminate the maintenance burden when the 5-flag set changes.
5. **`config_set.py:9` + `ingest.py:192` stale `autonomous.ingest` references** — T40 dropped the legacy flat `autonomous.<flag>` keys from `_SETTABLE_KEYS`, but two docstring / comment references at known line numbers still mention them. Cosmetic but drift-tracking matters.
6. **brain_mcp `_on_config_change` extracted to module-level for direct test import** — T35 review noted that the watcher callback is a closure inside `__main__`, which makes it awkward to unit-test directly. Extract to a module-level function so test imports are clean.
7. **`_resolve_config` returns live `ctx.config` reference** — T39.5 made `apply_patch._resolve_config` read live `ctx.config` (no longer a defaults-only snapshot). Confirm no future consumer mutates the returned reference; consider returning a frozen / deepcopy if the contract should be immutable.
8. **Free-threaded Python (PEP 703) consideration for Gap 3** — T39.5 made the no-lock decision for the `_cached_ctx` invalidation hook based on the GIL guarantee. PEP 703 (free-threaded CPython) is opt-in in 3.13 but may become default in 3.14+; revisit the lock-free assumption when free-threaded becomes the default.
